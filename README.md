# Ptuch Editor

Qt 6 desktop-текстовый редактор с AI-подсказками (MVP).

## Требования

- **C++20**
- **Qt 6** (Widgets), собран в `/Users/alexanderrabinov/Workspace/Qt/6.11.2-arm64`
- **CMake ≥ 3.16** (рекомендуется Ninja)
- **llama.cpp** — лежит в `third_party/llama.cpp` и подключается через `add_subdirectory`

## Возможности (текущее состояние)

- **Центральный виджет** — `QPlainTextEdit` (`setCentralWidget`).
- **Верхняя панель состояния** — `QToolBar`: индикатор состояния
  (Ready / Waiting / Generating / Error), кнопки **Generate** и
  **Clear Suggestion**, `QLineEdit` и `QComboBox`; компоновка через
  layouts (без абсолютного позиционирования).
- **Статусная строка** (`QStatusBar`) с описанием текущего события.
- **Три стиля оформления** — модуль `src/UI/theme.h/.cpp` (единый
  источник цветов), выбор в Settings (`ui/style`, комбобокс **Стиль**,
  применяется сразу): **default** — системные цвета шрифтов и
  контролов (палитра возвращается к системному снимку до темизации,
  stylesheet'ы снимаются), **ПТЮЧ** (дефолт) — глубокий
  антрацитово-фиолетовый фон, кислотно-жёлтый accent,
  электрик-синий secondary, светлый текст, **светлый** — светлые
  фоны с фиолетовым подтоном, тёмный текст и те же акценты в
  читаемых на светлом версиях; контрастность обеих темизированных
  схем проверяется тестом по WCAG. Реализация — через
  `QPalette` (базовые роли приложения; ghost-подсказка красит по
  `Base`/`Text` и совпадает с редактором) **и** stylesheet
  (состояния контролов: hover / pressed / disabled / focus;
  состояния контроллера на индикаторе: error — красный, generating —
  электрик-синий; зона набора без визуального шума — плоская, без
  `:focus`-обводок). Панель стилей и диалоги используют те же цвета
  (`Theme::panelStyleSheet`/`dialogStyleSheet`). Абсолютного
  позиционирования нет — только layout'ы и правила. Декор
  (скругления, градиент accent-кнопки) есть в темизированных
  схемах; default снимает stylesheet'ы вообще.
- Слой подсказок MVP: `SuggestionController` + `PlainTextEditorAdapter`
  (доступ к тексту/курсору редактора) + абстракция `ITextGenerationBackend`
  с mock-реализацией `MockTextGenerationBackend` (асинхронная «генерация»
  на `QTimer` **в отдельном потоке**, без модели и без блокировки UI).
  - debounce 500 мс после паузы в наборе;
  - **ghost-подсказка** рисуется `SuggestionOverlay` поверх viewport'а
    редактора: полупрозрачный текст у курсора на непрозрачном фоне
    `QPalette::Base` (документ под подсказкой не наезжает на призрак и
    не портит читаемость; хвост строки после подсказки остаётся виден).
    Первая строка — сразу за курсором, последующие — по левому краю;
    длинный текст переносится по ширине viewport и **не выезжает за
    правый край экрана**; после прокрутки viewport overlay остаётся
    выровненным по нему, документ при этом не меняется до принятия;
  - **Tab** — принять подсказку (`acceptSuggestion`), **Shift+Tab** —
    альтернатива, **Escape** — отклонить и отменить запрос
    (`rejectSuggestion`), **Ctrl+Space** — немедленный запрос, минующий
    debounce; потеря фокуса редактором (клик по панели, диалог,
    переключение окна) прячет показанную подсказку, гасит debounce и
    отменяет запрос «в полёте» (`SuggestionController::onFocusLost`);
    перевод клавиш и фокуса — в `MainWindow::eventFilter`,
    контроллер виджетов не видит; Tab без показанной подсказки
    не перехватывается (вставляется табуляция); ввод символа и движение
    курсора очищают подсказку;
  - сигналы `suggestionStarted/Ready/Failed/Cleared` и `stateChanged`;
  - явный `requestId` в каждом запросе: устаревшие ответы backend'а
    отбрасываются, даже если тот игнорирует `cancel()`;
  - логирование переходов состояний — категория `ptuch.suggestion`:
    `state: Idle -> Debouncing (id=5)` в каждой смене состояния,
    `cancel: активный запрос id=N отменён` и `stale: ответ id=N
    отброшен` — по журналу виден весь сценарий и гонки (видно по
    умолчанию: `grep ptuch.suggestion`);
  - DI: mock меняется на реальный backend через
    `SuggestionController::setBackend()` без изменения потребителя;
  - `MainWindow` не содержит логики inference — только wiring сигналов.
- **Реальный backend llama.cpp** — `LlamaBackend` реализует
  `ITextGenerationBackend` и подставляется через тот же `setBackend()`
  (DI-точка), как только модель загружена:
  - путь к GGUF: `PTUCH_MODEL_PATH` (файл) / `PTUCH_MODEL_DIR` (папка)
    → настройки `QSettings` (орг. `PtuchAI`, ключ `llama/modelPath`) →
    сканирование папки `models/` проекта;
  - модель загружается **один раз** queued-вызовом в отдельном потоке
    `llamaWorker` (UI не блокируется, sleep в UI нет); при
    отсутствии/ошибке загрузки остаётся mock-бэкенд (fallback +
    сообщение в статусной строке);
  - inference (`llama_decode`, sampling) — **только** в worker-потоке:
    `generate()` из UI переносится queued-событием, `cancel()` —
    атомарный флаг, который читает цикл генерации между чанками
    prompt processing и токенами;
  - `requestId` + отмена: устаревший запрос не стартует, отменённый
    возвращает `stopReason="cancelled"`; потребитель сверяет
    `requestId` независимо;
  - `llama_model`/`llama_context` — RAII (освобождение в потоке
    объекта при закрытии: `closeEvent → stopLlamaWorker`), один
    контекст на объект и строго последовательная обработка запросов —
    параллельного доступа к контексту нет;
  - лимиты: `n_ctx` зажат (256..8192 и не больше контекста обучения),
    промпт обрезается под `n_ctx` (сверху, ближе к курсору), генерация
    ≤ 512 токенов; в UI — только `ITextGenerationBackend`;
  - логирование категорией `ptuch.llama`: путь и время загрузки,
    `n_ctx`/потоки, число токенов промпта, время prompt processing,
    время генерации, причина остановки, поток выполнения.
- **Диалог настроек** — `SettingsDialog` (кнопка **Settings** в панели,
  хранение `QSettings`, ключи/дефолты/диапазоны — `AppSettings`):
  - поля: путь к GGUF-модели (кнопка выбора файла `…`, пусто —
    авто-поиск как при старте), размер контекста, максимум новых
    токенов, temperature, top-p, число GPU-слоёв (−1 = «все слои»),
    интервал debounce, переключатель автоматических подсказок и
    комбобокс стиля (`ui/style`: default / ПТЮЧ / светлый,
    применяется сразу — без перезапуска);
  - **проверка диапазонов**: `QSpinBox`/`QDoubleSpinBox` ограничены
    диапазонами `AppSettings`, а `AppSettings::load()` дополнительно
    санирует правленый руками файл настроек — некорректное значение
    не доедет ни до контроллера, ни до `LlamaBackend`
    (защита в глубину, см. `app_settings.h`);
  - кнопка **Test Model**: загрузка GGUF на **временном** `LlamaBackend`
    в собственном потоке (приложение продолжает генерировать на своём
    backend'е — активная генерация не отменяется и модель не
    перезагружается); прогресс/успех/ошибка загрузки показываются
    цветной меткой рядом с кнопкой, поток останавливается
    `requestStop → quit → wait` (в т.ч. в деструкторе диалога);
  - настройки сохраняются между запусками (`save()` + `sync()`);
  - **обновление не разрушает активную генерацию**: параметры
    генерации/debounce/авто применяются сразу (контроллер копирует их
    в каждый новый запрос, запущенный debounce-таймер не сбрасывается,
    выключение авто не отменяет запрос «в полёте» и не блокирует
    ручной `requestSuggestion`); перезагрузка модели
    (`MainWindow::reloadLlamaBackend`) — только при реальном
    изменении пути/контекста/GPU-слоёв и безопасным свапом
    (контроллер → mock: cancel + bump id → остановка старого потока →
    новый backend с новыми настройками, пока он грузится — mock).
- **Диагностика backend'а** — кнопка **Diagnostics** в панели →
  `DiagnosticsDialog` со снимком активного backend'а:
  - поля: имя backend'а, имя модели (только файл GGUF), размер
    контекста, число GPU-слоёв, prompt/generated токены, время
    обработки prompt'а, время генерации, токенов в секунду и
    последняя ошибка; метрики — последнего **успешного** запроса,
    пустые поля показываются как «—»;
  - кнопка **Копировать** кладёт текстовый отчёт в буфер обмена;
    отчёт формируется строго из полей снимка — **без указателей и
    внутренних адресов** (контролируется тестом);
  - снимок фиксируется при открытии диалога; данные собирает сам
    backend — `ITextGenerationBackend::diagnostics()`,
    потокобезопасная копия под мьютексом (UI не блокируется);
  - **режим отключаем**: опция `PTUCH_DIAGNOSTICS` (по умолчанию ON
    в Debug, OFF в Release) вырезает кнопку, диалог и их тесты —
    см. «Сборка»; API `diagnostics()` и метрики остаются.
- **Стилевые профили** — `StyleProfile` (id, имя, описание, цвет,
  prompt-инструкция, вес, enabled + опциональные поля LoRA-адаптера —
  см. «Стили и LoRA-адаптеры») и `StyleMixer` (домен без
  Qt-виджетов): встроенные «Пушкин», «Тютчев», «Киберпанк 80-х»,
  «Официальный стиль» — имена исторических авторов описательные, для
  живых авторов и публичных персон используются только нейтральные
  названия (юридические оговорки ТЗ); вес в `[0..1]`, сумма активных
  весов **предсказуема** (нормализация до 1.0 — в `normalize()` и на
  лету в `styleWeights()` → `SuggestionController::setStyleMix`),
  нулевые/выключенные в prompt не попадают; `buildInstruction()`
  собирает компактную инструкцию по одной строке на активный профиль
  и **не разрастается** от числа событий UI.
- **Панель стилей** — `StylePanel` (QWidget) в правом dock: строка на
  профиль (цветовой маркер, название, слайдер 0..100, числовое
  значение, нормализованная доля, чекбокс включения, кнопка сброса),
  внизу — сумма активных весов и кнопка **Reset Mix**; единый сигнал
  `styleMixChanged` (нормализованные веса) подключается в `MainWindow`
  к `SuggestionController::setStyleMix` — **смена микса очищает
  текущую ghost-подсказку** (контроллер убирает устаревшую и
  перепланирует запрос). Модель (`StyleMixer`) отделена от виджетов;
  циклических обновлений нет: обработчики меняют только подписи, один
  жест = ровно один сигнал (программные `setValue` — под
  `QSignalBlocker`), при отсутствии изменений сигнала нет. Панель
  приносит собственный тёмный stylesheet.
- **PromptBuilder** — детерминированный сборщик промпта режима
  автодополнения (`PromptInput` → `AutocompletePrompt`): system-правила
  просят **только продолжение** и запрещают пояснения, кавычки и
  метакомментарии; контекст документа входит ровно один раз — в user
  prompt, дословно и без декораций (system его не повторяет); язык
  документа сохраняется (шаблоны ru/en + автоопределение по символам
  контекста); смешанные стили добавляются блоком «Стили:» с
  нормализованными весами (формат `StyleMixer::buildInstruction`);
  параметры генерации санируются диапазонами `AppSettings`. Чистая
  функция без состояния и QSettings — поля выхода ложатся 1:1 в
  `GenerationRequest` (`systemPrompt` / `context` / параметры) при
  интеграции в контроллер.
- **Документы (v1, UTF-8 plain text)** — меню **Файл**: Новый
  (Ctrl+N), Открыть… (Ctrl+O), Сохранить (Ctrl+S), Сохранить как…
  (Ctrl+Shift+S); через `QKeySequence` — на macOS это Cmd-комбинации.
  Чтение/запись — `TextFileIO`: UTF-8 без BOM (русский текст
  сохраняется байт-в-байт, ведущий BOM при чтении отбрасывается),
  запись через `QSaveFile` — атомарная, сбой записи не портит
  существующий файл. Имя файла и modified-состояние — индикатором в
  правом краю статусной строки и в заголовке окна («имя[*]»,
  `setWindowModified`). Открытие/создание гасит показанную подсказку
  и ставит генерацию на паузу: контроллер выключен на время подмены
  текста — `textChanged` не планирует debounce, обратное включение
  ничего не запускает. `closeEvent` (и New/Open через общий
  `maybeSave`) спрашивает про несохранённые изменения: при Cancel
  окно остаётся и shutdown **не** выполняется — контроллер и потоки
  живы; при Save запись, при Discard — без сохранения. Ошибки
  чтения/записи показываются диалогом с текстом из `TextFileIO`.

### Стили и LoRA-адаптеры

**MVP: смешивание стилей — только через prompt.** Нормализованные веса
`StyleMixer` уходят в `GenerationRequest::styleWeights`, инструкции
активных профилей — блоком «Стили:» из `PromptBuilder`. Настоящее
взвешенное наложение LoRA-адаптеров требует **отдельного inference
backend'а** (который сам умеет загружать/переключать адаптеры) —
текущий GGUF-бэкенд (`llama.cpp`) и mock работают без адаптеров.

Под будущие адаптеры `StyleProfile` несёт опциональные поля (пустые/
нейтральные по умолчанию — существующие потоки не меняются):

| поле | смысл |
|------|-------|
| `adapterPath` | путь к файлу адаптера; пусто = адаптера нет (единственный признак `hasAdapter`) |
| `adapterType` | свободный тег формата (`"lora"`, `"dora"`, …) без привязки к библиотеке обучения |
| `baseModelId` | идентификатор базовой модели, под которую обучен адаптер |
| `promptTag` | триггер-метка для adapter-capable backend'ов (в prompt MVP не входит) |
| `adapterScale` | сила применения (типично 0..1; интерпретация и границы — за backend'ом) |

Явные ошибки вместо тихого игнора; **никакой фиктивной загрузки LoRA
нет**:

- `ITextGenerationBackend::supportsAdapters()` — `false` по умолчанию
  (mock и llama.cpp). Запрос с непустым `GenerationRequest::adapter`
  при `false` обязан дать явную `generationError` — обе реализации
  (`mock_text_generation_backend.cpp`, `llama_backend.cpp`) отвечают
  «бэкенд не поддерживает адаптеры (adapterPath=…)» и ничего не грузят;
- `SuggestionController::startRequest` проверяет адаптер
  **активного** стиля (`findActiveAdapter`) до отправки: backend без
  поддержки → `suggestionFailed` «не поддерживает adapterPath» и
  **0 запросов**; при поддержке `checkAdapterCompatibility` сверяет
  `baseModelId` адаптера с базовой моделью backend'а — несовместимость
  или неизвестность моделей даёт явную ошибку **до** инференса;
  успешный путь заполняет нейтральный `AdapterSpec` в запросе
  (загрузка — работа backend'а);
- `StylePanel` и `PromptBuilder` от полей адаптеров **не зависят**:
  панель рисует только нейтральные поля профиля, PromptBuilder
  (контракт закреплён тестами) кладёт в prompt лишь
  имя/инструкцию/вес — никаких типов и терминов библиотек обучения
  (`peft`, `transformers`, …) в них нет.

Контракт закреплён тестами: `StyleMixerTests` (поля по умолчанию,
`checkAdapterCompatibility`, `findActiveAdapter`),
`SuggestionControllerTests` (явные ошибки и заполнение `AdapterSpec`),
`MockBackend` и `LlamaBackendTests` (явный отказ backend'а).

## Сборка

```bash
cmake -S . -B build -G Ninja \
  -DCMAKE_PREFIX_PATH=/Users/alexanderrabinov/Workspace/Qt/6.11.2-arm64 \
  -DCMAKE_BUILD_TYPE=Debug

cmake --build build -j
```

При желании Ninja можно заменить на Makefiles — флаг `-G Ninja` просто убирается.

### Предупреждения

Для кода проекта включены `-Wall -Wextra` (MSVC: `/W4`).
На third_party (`llama.cpp`, `ggml`) предупреждения **не** распространяются.

### Режим диагностики (PTUCH_DIAGNOSTICS)

Кнопка **Diagnostics**, `diagnostics_dialog.*` и тесты диагностики
собираются под опцией `PTUCH_DIAGNOSTICS` — по умолчанию `ON` в Debug
и `OFF` в Release (переключается явно):

```bash
cmake -S . -B build ... -DPTUCH_DIAGNOSTICS=OFF  # выключить в Debug
cmake -S . -B build ... -DPTUCH_DIAGNOSTICS=ON   # включить в Release
```

При выключении UI-часть вырезается полностью: файлы диалога не
включаются в сборку, кнопка не создаётся, слоты тестов уходят в
`QSKIP`. `ITextGenerationBackend::diagnostics()` и сбор метрик
остаются (дешёвая инструментация — полезна и в журналах Release).

Покрытие:

- `DocumentState` — пустой документ, курсор в начале/середине,
  большой текст (обрезка префикса/суффикса, жёсткий потолок размера),
  зажим курсора в границах, смена generation id, исключение ghost-подсказки
  из контекста.
- `SuggestionController` — debounce (непрерывная печать не порождает
  запросов, после паузы ровно один), пустой контекст без генерации,
  мгновенный ручной `requestSuggestion` (и параметры запроса), рост
  generation id, игнорирование устаревшего ответа, отмена по
  `rejectSuggestion`, ошибки backend'а, `acceptSuggestion`, `setStyleMix`;
  обновление настроек «на лету»: `setDebounceInterval` (кламп
  границами, новый интервал применяется к следующему таймеру),
  `setAutoSuggestions` (гейт только debounce-пути: хвост таймера
  гаснет, ручной запрос и активная генерация живут) и
  `setGenerationParams` посреди активной генерации (запрос не
  отменяется, завершается со своим id, новые параметры уходят в
  следующий запрос). Гонки: `raceOfNewRequestCancelAndOldResponse` —
  новый запрос, отмена и приход старого ответа в одном сценарии
  (старый ответ отброшен, состояние нового не тронуто, свежий
  принимается), `staleErrorDroppedWhileNewRequestActive` — ошибка
  устаревшего запроса не ведёт текущий в Error;
  `focusLostHidesSuggestionAndCancels` — потеря фокуса скрывает
  показанную подсказку, гасит debounce и отменяет запрос «в полёте»
  (поздний ответ не воскресает подсказку);

  ответ отброшен, ручной запуск после shutdown невозможен;
  `stateTransitionsAreLogged` — каждый переход (`state: Idle ->
  Debouncing (id=N)`), отмена и stale-ответ попадают в категорию
  `ptuch.suggestion` (перехват handler'а + фильтр категории), ровно
  по строке на переход. Тесты идут без виджетов — только через
  интерфейсы.

  детерминированный результат `setResultText` (заданный текст
  байт-в-байт, без автоподсказки по контексту).
- `GhostSuggestion` — overlay рисует ghost у курсора (пиксельная проверка

  отбрасывание ведущего BOM, пустой документ. `QTEST_GUILESS_MAIN`,
  только `Qt6::Core` — слой не знает про виджеты.
- `TestPlan` (сквозные сценарии тестового плана, см. `TEST_PLAN.md`) —
  ошибка загрузки модели на битом GGUF из `PTUCH_MODEL_PATH`:
  статусная строка «остаёмся на mock», контроллер остаётся на mock и
  выдаёт детерминированную подсказку, окно закрывается без диалогов;
  закрытие приложения посреди активной генерации: `closeEvent ->
  shutdown` синхронно (бэкенд отвязан), поздний ответ mock'а
  отброшен, потоки остановлены деструктором. Ни фокуса окна, ни
  реальной модели/GPU — `PTUCH_MODEL_PATH` всегда указывает на
  заведомо битый файл.

Снимок ghost-подсказки для ручного просмотра (по желанию):

```bash
PTUCH_GHOST_SCREENSHOT=/tmp/ptuch_ghost.png ./build/GhostSuggestionTests
open /tmp/ptuch_ghost.png
```

Ручной сценарий проверки клавиш (в запущенном редакторе):

1. Печатаем слово и ждём ~1 сек — после курсора появляется подсказка:
   полупрозрачный текст на непрозрачном фоне цвета редактора (текст
   документа под ней не «наезжает» на призрак); документ при этом не
   изменился.
2. **Tab** — подсказка вставляется в документ, призрак исчезает.
3. Печатаем ещё слово, ждём подсказку, нажимаем **Escape** — подсказка
   исчезает, документ не изменился.
4. Снова ждём подсказку и вводим обычный символ — подсказка гаснет,
   символ попадает в документ.
5. Ждём подсказку и нажимаем стрелку — подсказка гаснет.
6. Без показанной подсказки нажимаем **Tab** — вставляется табуляция
   (клавиша не перехватывается).
7. Сразу после печати (не дожидаясь паузы) жмём **Ctrl+Space** —
   запрос стартует немедленно, подсказка приходит, не дожидаясь
   debounce.
8. Со показанной подсказкой кликаем по верхней панели (фокус уходит
   из редактора) — подсказка скрывается, индикатор возвращается в
   Ready; кликаем обратно в редактор и печатаем — всё работает заново.
9. Переходы состояний видны в журнале приложения:
   `... 2>&1 | grep ptuch.suggestion` — строки `state: ... -> ...`,
   `cancel:` и `stale:` показывают сценарий и гонки.
10. **Ctrl+N** — новый пустой документ («Без имени» в индикаторе);
    при несохранённых изменениях — вопрос Save / Discard / Cancel.
11. **Ctrl+O**, выбираем UTF-8 файл с русским текстом — текст в
    редакторе, имя файла в индикаторе и заголовке («имя[*]»),
    показанная подсказка очищена, генерация после загрузки не
    стартует.
12. Правим текст — индикатор показывает «изменён», в заголовке
    появляется маркер; **Ctrl+S** — записано, modified погашен;
    закрытие окна с несохранёнными правками — тот же диалог
    (Cancel оставляет окно полностью рабочим).
13. Со показанной подсказкой прокручиваем текст (колесо/скроллбар) —
    подсказка не «плывёт»: она следует за курсором, а фон текста
    под ней не просвечивает; **Escape** убирает подсказку.

Отключается опцией `-DPTUCH_BUILD_TESTS=OFF`.

### Модель (llama.cpp)

При старте `MainWindow` ищет GGUF и грузит её в фоне (первым
приоритетом — переменная окружения, затем настройки, затем `models/`):

| Источник | Ключ / правило |
| --- | --- |
| Окружение | `PTUCH_MODEL_PATH` (файл) или `PTUCH_MODEL_DIR` (папка с `*.gguf`) |
| Настройки | `QSettings` org `PtuchAI`, app `PtuchEditor`, ключ `llama/modelPath` |
| Папка проекта | первый `*.gguf` в `models/` (cwd, каталог бинаря или бандла) |

- Модель не найдена / не загрузилась — подсказки остаются на mock,
  причина пишется в статусную строку.
- `PTUCH_DISABLE_LLAMA=1` — не искать и не грузить модель (используется
  UI-тестами).
- Логи llama-части (загрузка, токены, тайминги, причины остановки):

```bash
./build/PtuchEditor.app/Contents/MacOS/PtuchEditor 2>&1 | grep ptuch.llama
```

### Настройки (QSettings)

Кнопка **Settings** в верхней панели открывает `SettingsDialog`; OK
применяет и сохраняет значения (единый источник — `AppSettings`,
`src/settings/app_settings.h`):

| Ключ | Дефолт | Диапазон |
| --- | --- | --- |
| `llama/modelPath` | пусто (авто-поиск) | — |
| `llama/contextSize` | 4096 | 256..8192 |
| `llama/maxTokens` | 64 | 1..512 |
| `llama/temperature` | 0.7 | 0.1..2.0 |
| `llama/topP` | 0.9 | 0.1..1.0 |
| `llama/gpuLayers` | −1 (все слои) | −1..128 |
| `suggestion/debounceMs` | 500 | 50..10000 |
| `suggestion/autoSuggestions` | включено | bool |
| `ui/style` | ПТЮЧ | default / ptuch / light |

- Значения вне диапазона (в т.ч. правленый руками файл) обрезаются в
  `AppSettings::load()` — до `LlamaBackend`/контроллера доезжают
  только валидные значения.
- Путь/n_ctx/GPU-слои применяются перезагрузкой модели **только при
  изменении** (безопасным свапом, активная генерация корректно
  завершается как устаревшая); остальные параметры — сразу, без
  отмены запроса.
- Гигиена тестов: `GhostSuggestionTests` и `SettingsTests` перед
  прогоном снимают **только** ключи приложения (`llama/*`,
  `suggestion/*`, `ui/*`) и возвращают их дословно в конце; дубль снимка
  пишется в файл (`tests/qsettings_backup.h`). Если прогон упал
  аварийно (SIGABRT до cleanup), настройки не теряются: при
  следующем запуске тестов они восстанавливаются из файла-снимка.

### Диагностика (кнопка Diagnostics)

Кнопка **Diagnostics** в верхней панели (собирается при
`PTUCH_DIAGNOSTICS=ON`) открывает `DiagnosticsDialog` — снимок
активного backend'а на момент открытия: имя backend'а и модели,
`n_ctx`, GPU-слои, prompt/generated токены, времена фаз,
токенов в секунду и последняя ошибка. Кнопка **Копировать** кладёт
тот же отчёт в буфер обмена; пустые поля отображаются как «—».
Новые цифры — после новых запросов (закрыть и открыть снова).

## Стандарт и автогенерация Qt

- `CMAKE_CXX_STANDARD 20` и `target_compile_features(... cxx_std_20)` —
  применяются только к таргету `PtuchEditor` (llama.cpp остаётся на C++17,
  чтобы не пересобирать third_party).
- `CMAKE_AUTOMOC` / `CMAKE_AUTOUIC` / `CMAKE_AUTORCC` включены явно и
  продублированы свойствами таргета.
- Глобальных mutable-объектов в коде нет: состояние backend'а инкапсулировано
  в pimpl, живущем в своём потоке; метатипы регистрируются в конструкторе.
